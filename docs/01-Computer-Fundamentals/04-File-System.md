# 文件系统

## 学习目标

完成本章后，你能够解释文件、目录、路径、权限与生命周期，用终端和 Python 观察相关系统信息，并把观察结果连接到 AI 产品的运行问题。

## 为什么学

AI 产品最终运行在真实计算机上。模型调用失败可能来自路径、编码、进程、网络或环境，而不一定来自模型。理解文件系统能把“程序不工作”拆成可以验证的小问题。

## 适用场景

适用于安装开发工具、分析错误日志、设计服务边界、上传文件、调用模型 API、容器化部署和生产故障排查。学习重点是建立可迁移的心智模型，而不是背诵某个系统界面。

## 核心概念

本章核心包括文件、目录、路径、权限与生命周期。每个概念都要回答四个问题：它管理什么、输入是什么、输出是什么、失败时能观察到什么。不要把抽象名词与某个具体产品等同。

## 生活案例

图书馆用书架、分类号和借阅规则管理书籍。这个类比帮助理解角色分工，但计算机按照明确规则执行，资源限制和错误状态比生活协作更严格，因此类比不能替代技术定义。

## 工作案例

AI PDF 产品需要接收文件、验证路径、保存元数据并安全删除。工程师应先保存错误、环境和输入，再提出假设，通过最小命令逐项验证，避免同时修改多个变量后无法确定原因。

## 理论

掌握跨平台路径和安全文件操作，避免覆盖与目录穿越。系统可以看成状态转换：输入进入边界，组件读取状态、执行规则、产生输出并记录可观察信号。可靠工程要求明确资源所有权、数据格式、失败传播和恢复策略。

## 代码示例

以下代码只读取或计算必要信息，不收集密钥与个人数据。使用 Python 3.13 或更高版本运行。

```python
from pathlib import Path
path = Path("demo-data") / "note.txt"
print(path.as_posix())
print(path.suffix)
```

预期输出：demo-data/note.txt 和 .txt。

## Demo

创建独立目录，保存代码为 main.py，运行 python main.py。先记录原始输出，再修改一个安全参数，比较结果。Demo 的完成证据包括命令、环境、输出和一句原因解释。

## 练习

1. 用自己的话画出本章输入、处理、输出和失败点。
2. 运行代码并标注哪些输出依赖当前机器。
3. 制造一个无破坏性的错误，保存错误文本并写出排查顺序。

验收：能够复现成功与失败，说明哪个观察支持最终结论。

## 项目

为“AI 产品运行环境体检器”增加一个与文件系统相关的检查项。输出使用稳定字段名，失败时返回清楚消息，不输出敏感环境变量值。

## 最佳实践

- 一次只改变一个变量，并保存操作前状态。
- 使用跨平台标准库，明确平台差异。
- 错误信息包含操作与上下文，不包含凭据。
- 先建立最小复现，再扩大到完整产品。

## 常见错误

- 把相关性当成原因，看到模型超时就立即更换模型。
- 只描述“不能运行”，不提供命令、环境和完整错误。
- 复制不理解的管理员命令，扩大故障或安全风险。
- 用某台电脑的绝对路径和全局依赖作为隐含前提。

## FAQ

**问：需要记住所有命令吗？**

答：不需要。先理解对象、状态与验证方法，再查阅命令参数。

**问：不同操作系统输出不一致是否表示错误？**

答：不一定。先区分语义是否一致，再记录平台差异。

## 总结

本章通过文件系统建立了从概念、观察到故障诊断的闭环。真正掌握的标准是能够解释边界、运行最小实验、复现失败并用证据支持结论。
