# 01 计算机基础 · 模块总结

> 成熟度：已完成

## 核心结论

计算机通过约定把信息编码为数据，程序通过运行时和操作系统使用硬件资源。用户看到的一个 AI 功能，背后至少经过界面、应用、运行时、操作系统、文件与网络等边界。任何边界都可能失败，因此排错必须依靠可观察证据。

## 能力模型

第一层是表示：能够解释位、字节、字符编码和 JSON。第二层是执行：知道源码、解释器、进程、线程和资源之间的关系。第三层是存储与通信：能安全处理路径、文件生命周期、DNS、端口和请求响应。第四层是工程环境：能使用终端、环境变量、虚拟环境和锁文件获得可重复结果。

## 排错流程

1. 原样保存命令、环境、输入、错误和时间。
2. 判断问题发生在配置、路径、编码、进程、网络还是应用逻辑。
3. 提出能够被证伪的最小假设。
4. 一次改变一个变量，运行最小实验。
5. 对比预期与实际，记录结论和恢复动作。
6. 把稳定检查加入测试、体检器或运行手册。

## 与 AI 产品的关系

模型超时可能是 DNS、代理或端口问题；文件问答失败可能是路径、权限或编码问题；线上与本地结果不同可能是运行时、依赖或环境变量不同。基础能力让你在更换模型之前先找到真实原因。

## 自我验收

你应能解释计算机分层，运行各章 Python 示例，识别平台差异，制造并修复一个安全故障，完成环境体检器，并说明它不应收集哪些数据。

## 后续连接

Python 模块将把这些系统对象转化为变量、函数、模块和可测试程序；Git、Linux 与 Web 模块会继续扩展可重复协作和网络应用能力。

复习时从任一故障反向追踪：用户看到了什么，应用记录了什么，运行时接收了什么，系统资源是否满足，外部依赖是否响应。若无法指出证据来自哪一层，就还没有完成定位。这个分层方法会贯穿后续 Python、Web、智能体、部署与可观测性模块。
