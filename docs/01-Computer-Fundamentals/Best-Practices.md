# 01 计算机基础 · 最佳实践

> 成熟度：已完成

## 环境记录

每次复现问题记录操作系统、架构、Python 版本、当前目录、命令、时间和完整错误。只记录解决问题所需数据，不复制全部环境变量或个人目录内容。

## 路径与文件

使用 pathlib 构造路径，区分相对路径与绝对路径。写入前检查目标与父目录，重要文件采用临时文件加原子替换。文件上传验证大小、类型、名称和存储边界，用户输入不能直接决定任意系统路径。

## 进程与命令

普通任务使用最小权限。理解命令的输入、输出、错误输出和退出码。长任务支持取消与超时；启动后台服务要记录进程、端口和停止方法。

## 网络诊断

按 DNS、连接、TLS、HTTP、应用顺序定位。网络请求必须设置超时，重试只用于可重试错误，并考虑幂等与退避。不要用关闭证书校验作为长期修复。

## 编码与数据

文本边界明确使用 UTF-8，读写时显式指定编码。结构化数据验证类型、必填字段和大小；日志避免直接打印完整用户输入。

## 可重复环境

使用 Python 3.13+、uv、pyproject.toml 和锁文件。安装、运行、测试命令写入 README。项目不得依赖未声明的全局包。

## 安全排错

先在测试目录和示例数据上操作。涉及删除、权限、网络扫描或系统配置时确认范围与授权。任何诊断工具都应遵循数据最小化。
## 实践检查方法

最佳实践只有进入日常流程才有价值。每次开始项目时建立环境基线，把版本、依赖、运行和测试命令写入 README；每次处理故障时保留最小复现与结论；每次上线前使用清单检查路径、编码、端口、超时和秘密。团队评审时不只问“能否运行”，还要问其他机器能否重复、失败是否可定位、输出是否泄露信息、恢复是否明确。把频繁出现的人工检查下沉为测试或体检器，但保留需要判断和授权的人工确认点。验收时由另一位学习者按文档从空环境复现，确认步骤、输出与恢复方式都清楚。
