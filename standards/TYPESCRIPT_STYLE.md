# TypeScript 代码规范

## 编译与类型

所有项目启用严格类型检查，不使用无说明的 `any`。未知外部输入先声明为 `unknown`，再通过模式校验或类型守卫收窄。公共函数、组件属性和服务返回值必须有稳定类型，服务端与客户端共享契约时只维护一个事实来源。

## React 与 Next.js

React 组件保持小而专一，副作用集中在明确边界。Next.js 默认优先服务端组件，只有需要浏览器交互、状态或浏览器 API 时使用客户端组件。数据请求、缓存、错误和加载状态必须显式设计。

## 样式与可访问性

Tailwind CSS 类名按布局、尺寸、间距、颜色和状态的稳定顺序组织。交互元素使用语义化标签，键盘可以访问，表单具有标签和错误提示。响应式设计从窄屏开始验证。

## 工程质量

格式化、Lint、类型检查和测试必须能够通过统一命令运行。环境变量区分服务端私密值和可公开客户端值。调用模型或后端 API 时处理超时、取消、重复提交和错误响应，不在浏览器暴露供应商密钥。
