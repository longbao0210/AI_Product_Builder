# 命名规范

## 目录与文件

课程模块使用两位数加英文短横线名称，例如 `01-Computer-Fundamentals`。项目使用两位数稳定编号，Demo 使用三位数全局编号。Markdown 固定治理文件使用约定的大写名称，教学章节使用两位数和清晰英文短横线名称。

## 代码标识符

Python 模块、函数和变量使用小写蛇形命名，类使用大驼峰命名，常量使用大写蛇形命名。TypeScript 变量和函数使用小驼峰命名，组件和类型使用大驼峰命名。布尔值使用能够读成判断的问题式名称，例如 `isReady` 或 `hasPermission`。

## API 与配置

HTTP 路径使用复数资源名和小写短横线，JSON 字段使用小写蛇形或小驼峰时必须在单个项目内保持一致。环境变量使用大写蛇形命名并带清晰作用域前缀。数据库表名、事件名和指标名应能反映业务含义。

## 版本控制

分支使用 `feat/`、`fix/`、`docs/` 等前缀。提交遵循 Conventional Commits，主题使用命令式短句。已发布编号和公开路径不得因排序偏好随意修改。
